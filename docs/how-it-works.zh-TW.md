# cache-context 的運作細節

[English](how-it-works.md) · [回到 README](../README.zh-TW.md)

## 提示快取與快取壽命

Claude Code 會用快取讀取價重用對話中已快取的部分，大多數模型是一般輸入價的十分之一。快取在最後一次使用後保留 5 分鐘或 1 小時；超過時間才回來，下一則訊息就得用快取寫入價把對話重新寫進快取：5 分鐘快取是一般輸入價的 1.25 倍，1 小時快取是 2 倍。

快取壽命先看 Claude Code 本身採用的環境變數（`FORCE_PROMPT_CACHING_5M`、`CLAUDE_CODE_PROMPT_CACHE_TTL`、`ENABLE_PROMPT_CACHING_1H`）。都沒設定時，訂閱方案在額度內假設 1 小時，其他情況假設 5 分鐘。Claude Code 自己給出壽命時（切換模型時，以及在最後一次回應後 5 分鐘到 1 小時之間恢復、而 Claude Code 仍視為已快取時，代表是 1 小時），外掛改用它的值，但超出方案額度時除外。不論哪種，外掛都會依實際觀察修正壽命。

只追蹤主對話；subagent 有自己的快取。壓縮後外掛重新開始追蹤；切換模型後快取顯示為無法使用，因為已快取的內容對不上了。

## 續期什麼時候划算

一次續期會重送對話的最後一個請求，後面接上 Claude 的最後一則回覆。它用快取讀取價 `r` 讀一遍已快取的前綴，用快取寫入價 `w` 把那則回覆寫進快取，再加上請求本身幾十個 token。目前紀錄到的每一次續期都會重新寫入這則回覆，即使離上一次續期只隔 55 分鐘也一樣，所以外掛把它算進每一次續期；回覆的長度就是 Claude 最後一則回覆的輸出 token 數。

過期之後，前綴要用 `w` 重寫，每個 token 比命中多花 `w − r`。把續期一次的成本記為 `p`，整段前綴多花的錢記為 `L`。續期的總成本低於 `L` 時才值得送，所以最多連續送大約 `L / p` 次；只要你在一次續期的時間內回來的機率高於大約 `p / L`，續期就划算。`/cache-status` 會依你的模型、快取大小和最後一則回覆算出這兩個數字。

金額按 API 牌價計算；訂閱方案下是等值金額，不是實際收費。

## 自動續期的規則

- 在快取快過期時送出續期，次數到你設的上限就停（沒改過是每段閒置期間 12 次）。已知模型價格時，在續期總成本超過一次過期多花的錢之前也會停。
- 確認續期確實能延長快取之前，每段閒置期間只續期 1 次。
- 續期遇到用量上限被拒時，等額度重置後才再試，這次不算進上限；讀不到重置時間時，等下一次回覆後才再續。其他原因失敗算一次，下一次至少隔 1 分鐘。
- 開關和次數上限存在外掛自己的儲存區，Claude Code 重開或更新後仍保持，並套用到之後的工作階段，直到你關掉。
- 每個工作階段的快取倒數和面板是否開著也會存起來。Claude Code 重開、工作階段接回來後，還沒過期的快取會繼續追蹤和續期，原本開著的面板會重新打開。7 天沒出現的工作階段紀錄會被清掉。

## 閒置壓縮

使用 1 小時快取且上下文達到 20 萬 token（由 `CLAUDE_CODE_IDLE_COMPACT_MIN_TOKENS` 設定，最低 10 萬）時，Claude Code 會在快取壽命的 90%，也就是最後一輪結束後第 54 分鐘，把閒置的對話壓縮成摘要。自動續期要等到過期前 5 分鐘才送，續期也不會延後壓縮，所以不處理的話，對話會在第一次續期前就被壓縮。

因此只要有工作階段開著自動續期，外掛就在你的使用者設定裡關掉 Idle compaction（`/config` 裡的 `idleCompaction`），等沒有工作階段開著自動續期時再打開。這項設定本來就關著的話，外掛不會動它。當掉或被強制結束的工作階段，在下一個工作階段啟動或切換自動續期時，若已 5 分鐘沒有動靜就視為已結束。

如果這項設定由專案、本機或受管設定檔決定，外掛改不了，請在那裡設定 `"idleCompaction": false`，或把 `CLAUDE_CODE_IDLE_COMPACT_MIN_TOKENS` 調到高於你的上下文大小。如果在外掛關著這項設定時停用或移除外掛，請到 `/config` 手動打開。

## 上下文視窗

數字和 `/context` 顯示的一樣，在每輪主對話結束後從本機讀取，不會為此送出請求。這個區塊自己的文字有繁體中文、簡體中文和英文；其他語言顯示英文。

## 用量保護的完整流程

1. Claude 每次回覆後，讀取五小時用量。
2. 用量達到門檻（預設 97%，可設 50–99%）時，之後每個工具結果都附上一段只有 Claude 看得到的提醒，請它做完手上這一步、寫下進度和下一步，然後停下。
3. 再用 8 次工具，或用量到 99%，工具就會被擋下；第 3 次被擋就結束這一輪。
4. 這一輪結束後，工作階段進入暫停。暫停期間自動續期照常運作。
5. 「重置後自動繼續」開著時（預設開），外掛會在五小時額度重置後 30 秒送出繼續訊息；被拒時 5 秒後重試，之後每分鐘一次，最多 5 次。繼續訊息會標明來自這個外掛。

收尾或暫停期間，面板上有「立即停止」「這次不暫停」「立即繼續」「取消自動繼續」按鈕。「這次不暫停」會讓保護在這次重置前不再動作。

- 你自己送出訊息就會結束暫停，即使還沒重置。如果用量仍超過門檻，下一次回覆後保護會再次開始收尾。
- 七天用量用完時不會自動繼續。
- 保護是在每次回覆後讀取用量，所以單一一次很長的回覆可能在保護看到之前就超過門檻。
- 「重置後自動繼續」是本外掛自己的開關，不會改動 Claude Code 原生的「Continue automatically at usage limit」（`autoContinueAtUsageLimit`）：Claude Code 只讓 mod 關掉那個設定，不能打開。
- 用量保護的設定只在面板和 `/cache-guard`，`/config` 裡沒有對應的列，因為 Claude Code 不讓 mod 修改自己的 `userConfig` 列。
- 用量保護的文字只有繁體中文和英文。
